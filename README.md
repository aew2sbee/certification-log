# certification-log

IT資格の過去問を解いた記録から、**正答率と苦手な分野を自動で集計・可視化**する静的サイトです。
記録は GitHub で管理し、GitHub Pages で公開します。ビルド不要の HTML / CSS / JavaScript だけで動き、外部ライブラリは使っていません。

- 公開URL：https://<ユーザー名>.github.io/certification-log/
- 記録するのは **問題番号・正誤・得点・分野・分からない単語だけ** です。問題文や選択肢は載せません。

## 使い方の流れ

1. 過去問を解き、TSV に問題ごとの結果（OK / NG）を書く
2. 分からなかった単語を、その回の結果のすぐ右の列に書く
3. 分からない内容を AI に質問し、やりとりの要点を `notes/` にメモとして残す
4. push すると、正答率・分野別の正答率・苦手問題が自動で集計されてサイトに反映される

## ページ

| ページ | 内容 |
| --- | --- |
| トップ（`index.html`） | 資格ごとのカード：状態（学習中 / 合格）、合格日、正答率、**苦手分野（正答率の低い3分野）**、解いた問題数。学習中の資格は次の試験までの残り日数 |
| 資格ページ（`cert.html?id=202610_ap` など） | **分野別の正答率**（全体と初回）、記述式の分野別平均得点率と選択候補、苦手問題、問題セット・回ごとの正答率と合否判定、解答グリッド、メモの表示 |
| 単語帳（`glossary.html`） | 全資格の「分からない単語」の一覧。検索、資格での絞り込み、並び替え |

資格フォルダの名前は `年月_資格ID` です（例：`202610_ap`）。フォルダ名がそのまま資格ページの URL（`cert.html?id=202610_ap`）になり、トップには年月の新しい順に並びます。

## 記録ファイル（TSV）

1ファイルが過去問1回分（問題セット）、1行が1問です。Excel やスプレッドシートで作り、タブ区切りで保存します。

```tsv
No	分野	1回目	分からなかった単語	2回目	分からなかった単語	3回目	分からなかった単語
1	基礎理論	OK		OK			
2	アルゴリズムとプログラミング	NG	逆ポーランド記法	OK			
3	コンピュータ構成要素	NG	パイプラインハザード	NG	パイプラインハザード	OK	
```

| 列 | 内容 |
| --- | --- |
| 先頭の列 | 問題番号（見出しは何でもよい） |
| 見出しに「分野」を含む列 | その問題の分野（任意。下の「分野の決まり方」を参照） |
| 見出しに「単語」を含む列 | すぐ左の回の分からなかった単語。複数は `、` `,` `;` で区切る |
| それ以外の列 | 左から順に 1回目・2回目…の結果。`OK` / `NG`（`○` / `×` も可）。空欄はその回は解いていない |

- **回は見出しの文字ではなく、列の並び順で数えます**（見出しの数字を打ち間違えても集計はずれません）
- 新しい回を解いたら、右に「N回目」「分からなかった単語」の2列を足します
- 記述式の科目は得点を `14/20` のように書きます（cert.json の科目に `max` を書いておけば `14` だけでも可）
- 見出しに日付を入れると（`1回目(2026-09-06)`）その回の解答日として表示されます（任意）
- 見出しに「メモ」「備考」を含む列は読み飛ばします
- 文字コードは UTF-8 推奨です（Excel の「Unicode テキスト」「テキスト（タブ区切り）」で保存したものも読めます）

### ファイル名

- フォルダに置くだけで表示されます。どこかに登録する必要はありません
- ファイル名（拡張子なし）が問題セット名として表示されます（`R5.tsv` → R5）
- 科目が複数ある資格は、ファイル名の末尾に `-科目ID` を付けるとその科目の記録になります
  （`r7-autumn-a.tsv` → 問題セット r7-autumn の科目A、`r7-autumn-b.tsv` → 科目B）。付けなければ cert.json の最初の科目です

## 分野の決まり方

苦手分野を出すには、各問題の分野が必要です。次の順で決まります。

1. TSV の「分野」列に書いてあればその値
2. 空欄なら、cert.json の `sections[].fields` に書いた問題番号の範囲
   （応用情報の科目A は 問1〜50 テクノロジ、問51〜60 マネジメント、問61〜80 ストラテジ と設定済み）
3. どちらもなければ「（分野未設定）」

まずは範囲で大まかに分類し、細かく見たくなったら「分野」列を埋める、という使い方ができます。
1つの科目の中で大分類と細かい分野が混ざると比べにくいので、どちらかに揃えるのがおすすめです。

## cert.json

```json
{
  "id": "ap",
  "name": "応用情報技術者試験",
  "status": "studying",
  "passedOn": null,
  "passLine": 0.6,
  "passRule": "each",
  "sections": [
    {
      "id": "A", "name": "科目A", "type": "choice",
      "fields": [
        { "from": 1, "to": 50, "name": "テクノロジ" },
        { "from": 51, "to": 60, "name": "マネジメント" },
        { "from": 61, "to": 80, "name": "ストラテジ" }
      ]
    },
    { "id": "B", "name": "科目B", "type": "score", "max": 20, "required": ["情報セキュリティ"], "choose": 4 }
  ],
  "examDates": [
    { "label": "令和8年度後期 科目A", "from": "2027-02-06", "to": "2027-02-19" },
    { "label": "令和8年度後期 科目B", "from": "2027-03-03", "to": "2027-03-15" }
  ]
}
```

| キー | 内容 |
| --- | --- |
| id | 短い資格ID（フォルダ名の `年月_` より後ろ）。単語帳のラベルに大文字で表示 |
| name | 表示名 |
| status | `studying`（学習中）/ `passed`（合格） |
| passedOn | 合格日 `"YYYY-MM-DD"`。未定なら `null` |
| passLine | 合格基準（0〜1。0.6 = 60%） |
| passRule | `each` = 科目ごとに合格基準以上が必要 / `total` = 合計で判定 |
| sections | 科目の一覧。`type` は `choice`（選択式）/ `score`（記述式） |
| sections[].fields | 任意。問題番号の範囲ごとの分野（「分野」列が空のときに使う） |
| sections[].max | 記述式のみ・任意。1問の満点（TSV に `14` とだけ書いたときに使う） |
| sections[].required | 記述式のみ・任意。必須の分野 |
| sections[].choose | 記述式のみ・任意。必須以外から選ぶ問題数。指定すると「選択候補」を表示 |
| examDates | 試験日程。`from`〜`to` が受験期間。学習中の資格は次の試験までの日数を表示 |

## メモ（notes/）

- ファイル名は `<TSV のファイル名>-q<問題番号>.md`（例：`r7-autumn-a-q12.md` = `r7-autumn-a.tsv` の問12）
- 置くだけで、その問題に「メモ」ボタンが出ます
- AI に質問した内容と回答の要点を書きます。問題文や選択肢は転載せず、自分の言葉で書いてください
- 見出し・箇条書き・番号付きリスト・引用・表・コード・太字・リンクを表示できます

## 記録の追加方法

1. 新しい過去問を解いたら、その資格のフォルダに TSV を置く。同じ過去問の2回目以降は、TSV の右に列を足す
2. コミットして push する。数分で GitHub Pages に反映されます

## 新しい資格の追加方法

1. `certification/` に `年月_資格ID` のフォルダを作る（例：`202703_db/`）
2. 既存の資格フォルダから `cert.json` をコピーして編集する
3. TSV を置く

`src/` を変更する必要はありません。cert.json のないフォルダは資格として扱いません。

## ローカルでの確認方法

**リポジトリのルート**で簡易サーバーを起動し、`/src/` を開きます。

```sh
python -m http.server 8000
```

ブラウザで http://localhost:8000/src/ を開きます。

- HTML ファイルを直接ダブルクリックで開くと、データを読み込めないため表示されません
- ローカルでは `python -m http.server` のフォルダ一覧ページから TSV を見つけています（公開時は GitHub Actions が作る `index.json` を使います）。ほかのサーバーではフォルダ一覧の形式が違って動かないことがあります

## 集計ルール

- **正答率（選択式）**：OK ÷（OK + NG）。空欄（未解答）は分母に含めません
- **得点率（記述式）**：得点の合計 ÷ 満点の合計
- **選択式と記述式をまとめる場合**（トップの正答率、トータル）：1問ごとの得点率の平均
- **初回の正答率**：各問題を最初に解いたときの結果だけで計算します。2回目以降は答えを覚えていることがあるので、実力に近いのは初回です
- **苦手分野（トップ）**：正答率の低い順に3分野。分野が決まっていない問題は含めません
- **合否判定**：`each` は記録のあるすべての科目が合格基準以上で合格（その回に記録がない科目があれば「判定なし」）。`total` はトータルが合格基準以上で合格
- **一部だけ解いた回**：その回に解いた問題だけで計算し、「全◯問中」と表示します
- **苦手問題**：NG が2回以上、または最新の解答が NG の問題。記述式は得点率が合格基準未満を NG とみなします
- **選択候補**：`type: "score"` の科目で `choose` を指定すると、`required` 以外の分野から平均得点率の高い順に `choose` 個を表示します

## GitHub Pages の公開設定

GitHub Pages はブランチから公開する場合ルートか `/docs` しか選べないため、GitHub Actions で公開します。

1. GitHub の Settings → Pages を開く
2. Build and deployment の Source を「**GitHub Actions**」にする
3. main に push すると `.github/workflows/pages.yml` が動き、`src/` の中身と `certification/` を並べ、ファイルの一覧（`certification/index.json`）を作って公開します（Actions タブから手動実行も可）
4. 数分後に https://<ユーザー名>.github.io/certification-log/ で公開されます

ワークフローはファイルのコピーと一覧の作成だけで、ビルドはしていません。
